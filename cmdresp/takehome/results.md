# NTT-256 accelerator: results

Batched forward NTT of 256-coefficient polynomials over Z_q, q = 8380417 (FIPS 204 /
ML-DSA), as a host-activated Vitis HLS kernel on the command-response pattern.  Built with
Waveflow following `examples/stream_inband`; part xc7z020clg484-1, 10 ns clock, Vitis HLS
2026.1 (`vitis-run`).  This is the result of run 2, against prompt version 2.  Rebuild
everything with `python ntt_build.py --through summary`.

## Interface

**Streams.** `s_in` and `m_out` are 32-bit AXI4-Stream; AXI-Lite (`s_axi_control`) carries only
control and status.  Layouts below are from serializing schema instances
(`results/layout.md`), not from reading the schemas.

**Command header** (`NttCmdHdr`, 1 word).  Its TLAST is not inspected: a header with or
without TLAST is accepted.

| Bits | Field | Meaning |
| --- | --- | --- |
| 7:0 | `cmd_type` | `NTT` = 1, `END` = 2; any other value (0 included) is `BAD_CMD` |
| 23:8 | `tx_id` | command ID, echoed in the response or reported on error |
| 31:24 | `nbatch` | polynomials in the batch, valid 1..16; ignored on `END` |

Example: NTT, tx_id 0x1234, nbatch 16 = `0x10123401`; END = `0x00000002`.

**NTT command** = header, then `nbatch` input bursts, one per polynomial: 256 words, one
coefficient per word, the whole 32-bit word is the value (must be < q), TLAST on word 255.

**Response** to an NTT command = response header (`NttRespHdr`, 1 word, its own burst with
TLAST: `tx_id` bits 15:0, `nbatch` bits 23:16, e.g. `0x00101234`), written as soon as the
command header passes its checks; then `nbatch` output bursts in input order: 256 words, the
coefficient in bits 22:0 and bits 31:23 zero, TLAST on word 255.  `END` gets no response.

**Status registers** (AXI-Lite, from the S_AXILITE Registers table in `reports/csynth.rpt`;
pragmas in `gen/ntt.cpp`): `CTRL` 0x00 (ap_start / ap_done / ap_idle), `halted` 0x10 (1 =
halted on error), `error` 0x20 (code below), `tx_id` 0x30 (the failed command's tx_id), each
with an `_ctrl` ap_vld register at +4.  All three are cleared at the start of every activation.

| Code | Name | Raised when |
| --- | --- | --- |
| 0 | `NO_ERROR` | |
| 1 | `TLAST_EARLY` | TLAST on word k < 255 of a polynomial's input burst |
| 2 | `TLAST_MISSING` | word 255 of a polynomial's input burst has no TLAST |
| 3 | `BAD_PARAM` | `nbatch` = 0 or > 16 |
| 4 | `BAD_CMD` | `cmd_type` is neither NTT nor END |
| 5 | `BAD_COEFF` | an input word >= q |

**Host protocol.** Write `ap_start`; send commands, then `END`; wait for `ap_done`; read
`halted`, `error`, `tx_id`.  Expect one response header plus `nbatch` bursts per NTT command.
After an error, reset the stream path (the input may still hold words the kernel never read)
before the next `ap_start`.

## Design

`body()` in `ntt_body_impl.tpp` is one loop over commands (`CMDS`).  Per command it reads the
1-word header; returns on `END`; checks `cmd_type` then `nbatch` (BAD_CMD, then BAD_PARAM)
before writing anything; writes the response header; then loops over the polynomials
(`POLYS`), one at a time:

1. `load_poly` (loop `LOAD`, II = 1, 257 cycles): reads 256 words into buffer `a`, checking each
   word for `>= q` (BAD_COEFF) before its TLAST (TLAST_EARLY), and stopping at the first bad
   word.
2. `ntt_transform` (loop `NTT_STAGES`, 4 iterations of two stages, 1,117 cycles): the 8
   butterfly stages of FIPS 204 Algorithm 41, ping-pong between buffers `a` and `b`
   (a -> b -> a ...), so the result ends in `a`.  Each stage is a pipelined loop `STAGE_BFLY` of
   128 butterflies at II = 1 (137 cycles with its 9-cycle pipeline): `t = zeta * v mod q`,
   `u + t`, `u - t`.  The twiddle factor of group g in stage s is `ZETAS[2^s + g]`, a 256-entry
   ROM (`ntt_zetas.h`).  `mulmod` reduces the 46-bit product with 2^23 = 2^13 - 1 (mod q):
   three shift-and-add folds and one conditional subtraction, so the only DSPs are the 23x23
   multipliers'.
3. `store_poly` (loop `STORE`, II = 1, 258 cycles): writes `a` as one 256-word burst, TLAST on
   the last.

**How the throughput target is reached.**  One butterfly per clock needs two reads and two
writes per clock.  Each buffer is split into two banks of 128 words (`a0`/`a1`, `b0`/`b1`,
simple dual-port BRAM, one read and one write port each): coefficient i lives in bank
parity(i), the XOR of its 8 index bits, at address i >> 1.  A butterfly's indices j and
j + len differ in exactly one bit, so they are always in different banks, and every
butterfly reads each input bank once and writes each output bank once.  The two stage call
sites are inlined, so there are two copies of the butterfly hardware (a -> b and b -> a), 2
DSPs each.  One polynomial is then 257 + 1,117 + 258 = about 1,640 cycles, under the
1,700-cycle budget; nothing overlaps between polynomials, which the prompt allows.

**State.** Only the four 128 x 23-bit banks, used within one polynomial, and the status
registers.  Nothing is kept between polynomials, commands or activations.  Because a
polynomial's output burst is written only after its input is complete and checked, no output
burst is ever open when an error is detected.

## Verification

ALL PASS.

- Hand-computed examples: delta_0 -> all 1; (q-1) delta_0 -> all q-1; zero -> zero;
  delta_1 -> w_hat[0] = 1753, w_hat[1] = 8378664 and w_hat[2i+1] = q - w_hat[2i] for all i;
  delta_128 -> 4808194 for i < 128 and 3572223 for i >= 128.  PASS.
- Direct reference: the defining formula w_hat[i] = sum w[j] zeta^((2 brv8(i)+1) j) mod q in
  Python integers (no butterflies, no twiddle table), on 4 random polynomials, all q-1,
  alternating 0/q-1 and delta_255: exact match.  PASS.
- Convolution property, NTT(a*b mod X^256+1) = NTT(a) .* NTT(b), negacyclic product computed
  schoolbook, 3 random pairs: PASS.

**The checker rejects wrong outputs** (`results/checker_selftest.txt`): natural-order output,
an error path that does not halt, a partial polynomial left open after an early TLAST, a
kernel that drains its input after BAD_PARAM, and one output not reduced mod q: all
REJECTED.

## Assumptions

Run 1's Assumptions 1 to 9 are now requirements in prompt version 2 (see its revision
history).  What prompt version 2 still leaves to the agent, all interface or testbench
details:

1. **The banking scheme.**  The prompt asks for separate RAM ports for each butterfly's two
   reads and two writes; the parity banking (Design) is how, at 4 DSPs and 4 BRAM_18K for
   the buffers.  No output, error or timing depends on it beyond meeting the II = 1 target.
2. **Field widths.**  `nbatch` is 8 bits, so every value from 17 to 255 is BAD_PARAM; `tx_id` is
   16 bits.
3. **The response header** echoes `nbatch` as well as `tx_id`.
4. **The host's reset** is modeled, as the course does, by fresh streams for each activation;
   the testbench counts and discards the words a halted kernel left unread.
5. **An input that ends without END** (or inside a polynomial) makes the kernel wait for more
   words, as any streaming kernel does; the host always ends an activation with END, and every
   scenario's stimulus does (the error scenarios queue it behind the bad command).
